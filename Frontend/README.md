# Paint Rush Frontend

React + TypeScript + PixiJS 프론트엔드입니다. 팀원 최신 main `a519e2e`의 페이지·서비스 구조와 로그인·회원가입·로비를 기준으로 캐릭터 선택 및 인게임을 통합했습니다. Node.js 24 이상을 사용합니다.

## 미리보기

`Frontend/index.html`을 더블클릭합니다. 이미지·글꼴·React·PixiJS를 HTML에 포함하므로 서버 없이 열립니다. 시작메뉴 원본이 표시된 뒤 3초 후 로그인창이 나타나며, 별도 START 버튼은 없습니다.

**체험하기 → GAME → 캐릭터 카드 → Play → 매칭 화면 체험**으로 게임에 들어갑니다. **화면 체험 도구**에서 준비·게임·데스매치·사망/리스폰과 카메라 효과를 확인할 수 있습니다. 파일 체험에서는 인증·계정 저장·WebSocket 요청을 보내지 않습니다.

## 팀원 코드와의 통합

- 팀원 `src/pages`, `src/services`, `src/styles` 구조와 로비의 프로필·레벨 조회, 회원가입 비밀번호 확인을 유지합니다.
- 캐릭터 선택 화면은 Figma `57:5`, 인게임은 새 전투 콘티 `66:3`을 기준으로 합니다. 이미지 레이어 원본을 보관하고 실제 데이터와 조작을 연결합니다.
- 서버에서 `/characters`, `/cards`, `/users/me/deck`, `/users/me/profile`을 읽습니다. 등록 캐릭터, 카드 종류·코스트, 6장 덱과 중복 슬롯을 검증합니다.
- 매칭 전에 덱 PUT과 선택 캐릭터 PATCH의 응답을 확인합니다. 저장 실패 시 매칭하지 않습니다. 실제 서버의 저장된 덱을 사용합니다.
- 시작·로그인·로비 → 캐릭터 선택·덱 설정 → 매칭 → 10초 준비 → 게임·데스매치 → 종료·룸 퇴장·로비 복귀를 연결합니다.

## 인게임

- 상단 맵, 하단 손패 3장·다음 카드·코스트·채색 비율을 전투 콘티에 맞춰 배치합니다. 카드 목록은 사진의 **JUMPER·DASH·SLIDING**, Figma의 **CRISS CROSS·SWASTIKA·THE LINE** 여섯 장입니다.
- 체험에서는 JUMPER의 중심 5×5 점프, DASH의 상하좌우 정확히 4칸 이동, SLIDING의 대각선 1~5칸 이동과 세 공격 카드의 실제 타일 채색·손패 순환을 실행합니다. 이동 카드는 이동한 경로를 칠하며, 공격 카드는 플레이어 위치를 바꾸지 않습니다. THE LINE은 선택한 동서남북 방향으로 현재 칸을 제외한 앞 4칸을 칠합니다.
- 카드에 마우스를 올리면 빨간 점선·빗금으로 범위를 표시합니다. 이동 카드와 THE LINE은 맵의 표시된 칸에 마우스를 옮겨 경로·공격 범위를 확인하고 클릭해 실행합니다. CRISS CROSS와 SWASTIKA는 카드나 표시된 공격 범위를 클릭해 실행합니다. 터치에서는 카드를 눌러 범위를 표시한 뒤 타일을 누릅니다. Esc로 선택을 취소하며, 잘못된 목적지는 코스트나 손패를 소모하지 않습니다.
- 카드 코스트는 JUMPER 4, DASH 3, SLIDING 4, CRISS CROSS 5, SWASTIKA 6, THE LINE 3입니다. 체험에서도 코스트를 차감하고, 코스트가 부족한 손패는 비활성화합니다. 실제 서버의 카드 목록과 코스트도 이 값과 비교합니다.
- `/ws/game`에서 인증·기존 룸 조회·매칭·전체 상태·타이머·코스트·손패를 받습니다. 요청 중 중복 사용을 막고 서버 확정 전 위치·소유 타일·코스트를 임의로 변경하지 않습니다.
- 이동 카드는 선택한 타일을 `target_x`, `target_y`로 전송합니다. `player_moved`, `tiles_updated` 수신 후 전체 상태를 재확인하여 반영합니다.
- 채색 비율은 플레이어별 검증된 타일 수 / 전체 맵 타일 수입니다. 미채색 영역도 남기며 소유 행렬과 집계가 다르면 이전 화면을 유지하고 재확인합니다.
- 카메라 드래그·확대는 플레이어 위치와 분리됩니다. 사망·서버 연결 끊김·경기 종료에는 카드 입력을 막습니다.
- 화면 전체 높이를 사용하고 상단에 타이머·좌표, 중앙에 큰 20×20 맵, 하단에 손패·코스트·채색 비율을 배치합니다. 작은 화면에서는 하단 상태 표시와 손패를 두 줄로 배치하여 맵을 크게 유지합니다.
- 승인한 시야 구조를 실제 인게임에 적용했습니다. 전체 20×20 맵으로 시작하며, 맵 위 휠은 커서 기준 1~3배 확대·축소, 우클릭 드래그는 시야 이동, Space는 배율을 유지한 내 위치 복귀입니다. 맵 가장자리를 벗어나는 시야는 보정하며, 캐릭터 이동이 자유 카메라를 자동으로 끌어가지 않습니다.
- 확대할 때만 오른쪽 아래에 실제 타일 색·플레이어 위치·현재 시야를 표시하는 미니맵이 나타납니다. 미니맵 클릭으로 위치를 이동하고, 미니맵의 복귀 아이콘으로 전체 맵 배율을 복원합니다. 상단 시야 모드 버튼과 슬라이더는 사용하지 않습니다.
- 하단 손패는 시안처럼 간결하게 배치합니다. 선택한 카드는 10% 커지고 6px 올라오며 `선택됨` 표시와 테두리로 강조합니다. 맵으로 커서를 옮겨도 선택을 유지하고 사용·Esc 취소·사망·연결 중단 시 해제합니다. 원본 공격 카드 이미지는 유지합니다.
- 기본 체험 맵은 벽 없는 임시 20×20 평지입니다. 새 맵 디자인은 추가하지 않습니다.
- 현재 코스트와 게임 상태에서 사용할 수 있고 유효한 대상이 있는 손패는 초록색으로 표시합니다. 목적지를 먼저 고를 필요 없이 카드 호버부터 시작할 수 있습니다. 단색 소유 영역 위에도 점선·빗금이 구별되도록 흰 배경을 겹칩니다.
- 결과 콘티 화면 제작은 사용자 요청으로 이번 범위에서 제외합니다. 기존 임시 결과 표시와 퇴장·로비 복귀는 유지합니다. NPC 알고리즘은 추가하지 않습니다.
- 확인한 GitHub main은 이전 카드 목록과 1칸 이동 규칙을 사용합니다. 실제 서버 연동에는 여섯 카드 ID와 능력의 백엔드 등록이 필요하며, 호환되지 않는 목록은 안내하고 매칭을 막습니다. 서버 경기는 프론트에서 임의 판정하지 않습니다. 자세한 계약은 [GAME_PROTOCOL.md](GAME_PROTOCOL.md)를 참고합니다.

## 인증

`POST /api/v1/auth/login`, `POST /api/v1/auth/register`에는 `{ username, password }`만 전송합니다. 아이디는 영문·숫자·밑줄 3~20자, 비밀번호는 8~32자입니다. 가입 시 비밀번호 확인은 프론트에서 비교하고 서버에 보내지 않습니다. 가입 성공 후 반환된 아이디를 채우고 비밀번호를 지웁니다.

JWT는 React 메모리에 보관합니다. 로그아웃·새로고침 시 제거되며 비밀번호와 토큰을 브라우저 저장소에 저장하지 않습니다. 오류·만료·시간 초과를 안내합니다.

## 빌드와 검증

```sh
npm ci
npm test
npm run build
npm run test:ui
```

`src/` 변경 후 빌드하면 `index.html`과 `dist/index.html`이 갱신됩니다. 팀원 인증·계정 테스트에 덱 저장·실시간 상태 검증·화면 흐름 테스트를 더했습니다. UI 검증은 모의 HTTP/WebSocket 및 파일 미리보기를 사용하며 서버를 실행하지 않습니다. 실제 DB 인증·다인전 검증을 대신하지 않습니다. Windows에서는 설치된 Edge를 사용합니다.

## 개발·배포

직접 개발 서버가 필요할 때만 `npm run dev`를 실행합니다. Vite는 `/api`, `/users`, `/characters`, `/cards`, `/ws`를 `127.0.0.1:8000`으로 전달합니다. 백엔드를 자동으로 실행하지 않습니다. 배포 시 `dist`를 제공하고 `nginx.conf.example`의 API·WebSocket 경로를 기존 설정에 추가합니다. 백엔드 소스와 DB는 이번 통합에서 변경하지 않았습니다.
