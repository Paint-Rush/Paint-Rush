# Paint Rush Frontend

React + TypeScript + PixiJS 게임 프론트엔드입니다. Node.js 24 이상을 사용합니다.

## 서버 없이 화면 미리보기

`Frontend/index.html`을 더블클릭합니다. React와 CSS가 포함되어 있어 화면을 여는 데 서버나 인터넷은 필요하지 않습니다. 파일 주소에서는 실제 인증 요청을 보내지 않고 서비스 주소에서 로그인하도록 안내합니다.

로그인 아래 **게임 화면 체험하기 →**를 누르면 게임 로비로 이동합니다. 캐릭터·덱을 선택하고 **매칭 화면 체험**을 누르면 매칭(3초) → 준비(10초) → 게임(5분) → 결과 화면으로 이어집니다. 하단 **화면 체험 도구**에서 각 화면으로 건너뛰거나 사망·리스폰, 카메라 흔들림·왜곡·충격을 확인할 수 있습니다. 앱이나 서버를 별도로 실행할 필요가 없습니다.

## 범서 담당 구현 범위

| 항목 | 구현 |
|---|---|
| 매치메이킹 | 제공 콘티의 도시·좌우 잉크 흐름·대기 시간, 캐릭터·현재 덱, 취소 |
| 준비 | 제공 콘티의 4분할 캐릭터·중앙 VS·10초 카운트다운, 2~4명 레이아웃 |
| 맵 | 20×20 기본 JSON, 파일 불러오기, 타일 정의·크기·스폰 검증, 소유 색상 레이어 |
| 카메라 | 아바타와 별도 좌표, 부드러운 추적·드래그·버튼으로 이동·줌·다시 추적 |
| 화면 효과 | 흔들림, 왜곡, 충격 링·줌, 모션 감소 설정 존중 |
| 아바타 | 서버 위치를 표시, 직접 키보드 이동 없음, 사망·10초 리스폰 표시 |
| 게임 HUD | 남은 시간·데스매치·코스트·순위·카드 UI·대상 타일 선택 |
| 결과 | 단독 승자·나머지 패배, 모든 동률 기준별 통계, 서버 경험치 표시, 로비 복귀 |

캐릭터·도시 벡터는 콘티 기반 임시 아트이고 결과창은 콘티가 없어 임시 구성입니다. 카드 이름·코스트·체험 효과도 정식 카드 기획이 나오면 교체합니다. 캐릭터 선택은 임시 4종이며 아바타나 카드가 실제로 서버에 등록되었다는 뜻은 아닙니다.

**실시간 연결 상태:** 현재 백엔드에 매치메이킹/WebSocket 경로가 없으므로 실제 다인전 연결은 아직 불가합니다. 프론트는 기존 `GameRoom` 구조를 받는 검증 어댑터와 연결 코드를 준비했습니다. 서버 플레이를 선택하면 실제 연결만 시도하며 실패를 체험 경기로 바꾸지 않습니다. 서버 담당자에게 전달할 경로·이벤트·필드 제안은 [GAME_PROTOCOL.md](GAME_PROTOCOL.md)에 있습니다. 게임 상태·승패·레벨·로그 저장의 최종 권한은 서버에 있습니다.

## API 연동

`POST /api/v1/auth/login`에 `Content-Type: application/json`과 `{ username, password }`를 전송합니다. 백엔드 규칙에 따라 아이디는 영문·숫자·밑줄 3~20자, 비밀번호는 8~32자입니다. 비밀번호의 공백은 보존합니다.

성공 응답의 `access_token`과 `token_type: bearer`는 React 메모리에 보관하며 게임 로비로 이동합니다. 로그아웃 또는 새로고침하면 토큰이 사라집니다. 비밀번호와 토큰은 브라우저 저장소에 저장하지 않습니다. 새로고침 후 로그인 유지는 아직 구현하지 않았습니다.

확인 버튼 아래의 “계정이 없다면? 회원가입”을 누르면 같은 형태의 회원가입 화면으로 전환됩니다. `POST /api/v1/auth/register`로 아이디·비밀번호를 전송하고 가입 성공 시 로그인 화면으로 돌아옵니다. 서버에서 반환한 아이디를 채우고 비밀번호는 지웁니다. “이미 계정이 있다면? 로그인”으로 돌아갈 수도 있습니다.

401, 중복 아이디(409), 422, 서버 오류, 비정상 응답, 연결 실패와 10초 시간 초과를 처리합니다. 요청 중에는 입력·제출·화면 전환을 비활성화합니다. 파일을 직접 연 상태에서는 두 화면을 미리 볼 수 있으며 실제 가입·로그인은 서비스 주소에서 수행합니다.

## 개발 연결 (필요할 때 직접 실행)

```sh
npm ci
npm run dev
```

`/dev.html`에서 개발 화면이 열립니다. Vite는 `/api` 요청을 `http://127.0.0.1:8000`으로 전달합니다. 백엔드는 별도로 실행되어 있어야 하며, 이 설정이 백엔드를 실행하지는 않습니다. 백엔드 주소가 다르면 `vite.config.ts`의 proxy를 수정합니다. `npm run preview`에도 동일한 프록시가 적용됩니다.

## 빌드 및 테스트

```sh
npm test
npm run build
npm run test:ui
```

`src/`를 수정하고 빌드하면 `index.html` 및 `dist/index.html`이 갱신됩니다. HTML은 자동 생성 파일입니다. 게임 코드와 스타일은 `src/game/`에 있습니다. PixiJS는 [v8 공식 Application API](https://pixijs.com/8.x/guides/components/application)를 사용합니다.

단위 테스트는 API, JSON 맵과 룸 검증, 큐·준비·게임·리스폰 시간, 코스트, 카드 순환, 모든 동률 판정, 카메라 독립성을 검증합니다. UI 테스트는 실제 브라우저에서 파일 미리보기·모바일 레이아웃·카드·카메라·사망·결과와 모의 WebSocket 메시지를 검증합니다. **두 테스트 모두 서버를 실행하지 않으며 실제 백엔드·DB 인증과 다인전 테스트를 대신하지 않습니다.**

Windows UI 테스트는 설치된 Microsoft Edge를 사용합니다. 다른 환경은 `npx playwright install chromium`으로 테스트 브라우저를 준비하세요. 화면 캡처는 `test-results/`에 생성되며 Git에는 포함하지 않습니다.

## 배포

`dist`를 Nginx의 정적 파일 root로 제공하고 `/api/`를 FastAPI로 전달합니다. `nginx.conf.example`의 location 설정을 기존 server 블록에 추가하고 `backend:8000`을 실제 백엔드 주소로 맞춥니다. 프론트와 API를 같은 출처에서 제공하므로 별도의 CORS 설정은 필요하지 않습니다. 백엔드 API나 DB 코드는 변경하지 않습니다.
